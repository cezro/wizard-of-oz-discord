# Specification: Automated Discord Daily Standup Summarizer

## 1. Project Overview & Context

We share daily asynchronous Daily Standup Meetings (DSMs) in a designated Discord channel. This specification defines a stateless, scheduled integration that automatically collects today’s standup posts, synthesizes them using the Google Gen AI SDK (Gemini), and broadcasts a structured summary back to the team.

The primary objective is to eliminate manual oversight and provide an automated, clean, end-of-day summary of team progress.

---

## 2. System Architecture & Boundaries

### A. Scheduling & Triggering (Ingress)

- **Cadence:** Automatically execute once per day, Monday through Friday, at end-of-day (Target: 5:00 PM / 17:00 Philippine Standard Time (PST) / UTC+8).
- **Security:** If deployed as an HTTP endpoint (e.g., Vercel Serverless, Cloudflare Workers, Firebase Functions), the route must require a secure authorization token passed via headers (e.g., `Authorization: Bearer <CRON_SECRET>`) to prevent webhook spam.
- **Timezone Safety:** Per-guild IANA timezone (default `Asia/Manila`) is validated at pipeline start and used for embed date formatting. The fetch window is anchored to cron execution time, not server-local clock.

### B. Message Ingestion & Sanitization

- **Fetch Window:** Retrieve messages from the designated Discord channel within an **inclusive rolling 24-hour window** anchored to the cron execution instant (`windowStart` = now − 24h, `windowEnd` = now). Both bounds are enforced during Discord pagination and again after sanitization. Invalid IANA timezone config fails the pipeline with a clear error.
- **Noise Filtering:** Strip out:
  - System messages (e.g., user joined channel pins).
  - Bot-generated content (including previous summaries generated by this tool).
  - Posts containing only reactions/emojis with no text context.
- **Chronological Ordering:** Order retrieved messages from oldest to newest before passing them to the AI model to preserve conversational context and chronological thread continuity.

### C. AI Integration (Gemini)

- **SDK & Model:** Use the official `@google/genai` SDK with `gemini-2.5-flash` or `gemini-3.1-flash-lite`.
- **Model Config:** Set `temperature: 0.1` to maximize factual determination and minimize hallucinations.
- **System Prompt Requirements:** Instruct the model to parse the clean message logs and generate a bulleted summary structured exactly under these markdown headings:
  - ### Key Accomplishments (Completed tasks)
  - ### Active Focus Areas (In-progress work)
  - ### Blockers & Dependencies (Explicitly calling out bottlenecks)
- **Attributions:** Every bullet point must attribute tasks to the corresponding team member using their raw Discord handle string format (e.g., `<@user_id>` or `@username` as ingested) to ensure native Discord tagging works in the response.

### D. Summary Broadcast (Egress)

- **Delivery Mechanism:** Execute a POST request via the Discord Bot API or an Incoming Webhook to the source channel.
- **Presentation:** Wrap the synthesized response in a **Discord Rich Embed** object for a clean, professional UI rather than unformatted raw body text.
  - _Embed Title:_ `📊 Daily Standup Summary - [Current Date]`
  - _Embed Description/Fields:_ Contain the structured markdown output from Gemini.

## 3. Key Edge Cases to Handle

| Edge Case Scenario            | Required System Action                                                                                                                                                                                                                              |
| :---------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Zero-Post Days**            | If no user messages remain after sanitization, halt execution immediately. Do **not** call the Gemini API. Broadcast a friendly notification to the channel (e.g., _"No standup updates recorded for today! Hope everyone had a productive day."_). |
| **Discord Rate Limits**       | Implement a safe pagination mechanism if fetching more than 100 messages. Handle `429 Too Many Requests` gracefully by catching the error or building in minor backoff delays.                                                                      |
| **Future-Proofing for State** | Modularize data flow. Keep data ingestion logic completely separate from processing and broadcasting pipelines. Ensure a clean interface or data object is passed between layers so a storage layer (e.g., Firestore) can easily tap into it later. |

---

## 4. Technical Stack Preferences

- **Runtime:** Node.js (TypeScript preferred for type safety).
- **Primary Libraries:**
  - `discord.js` (or lightweight alternatives like raw `fetch`/`axios` requests to Discord API to keep cold starts fast).
  - `@google/genai` (Official Google Gen AI SDK).
  - `dotenv` for managing environment variables locally.

## 5. Required Environment Variables (`.env`)

See [`.env.example`](../.env.example) and [env-setup.md](env-setup.md) for the current list. Per-server channel and timezone are configured via `/standup-config set` in Discord (stored in Supabase), not in env vars.

```env
DISCORD_BOT_TOKEN=your_discord_bot_token
DISCORD_APPLICATION_ID=your_discord_application_id
DISCORD_PUBLIC_KEY=your_discord_public_key
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SECRET_KEY=your_supabase_secret_key
GEMINI_API_KEY=your_google_gemini_api_key
CRON_SECRET=your_secure_cron_secret
```
