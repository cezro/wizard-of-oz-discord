# Audit: Stuck bot / missed reminders (2026-06-17)

## Summary

Production failures on 2026-06-17 split into three user-visible symptoms:

1. **Automatic reminders not sent** — scheduler logged `tick skipped, previous still running` for hours.
2. **`/standup start` stuck on "thinking…"** — defer succeeded but follow-up never completed.
3. **Process crashes** — Supabase `ws` regression and `editDeferredInteraction` body double-read.

Root cause chain: **global tick mutex** + **one-minute schedule windows** + **slow member pagination** on every daily reminder.

## Root causes

### RC-1: Member list pagination on daily reminders

`runDailyReminder` called `getExpectedReporterIds` → `fetchMemberIdsWithRole`, paginating the entire guild via REST (`GET /guilds/{id}/members`) to ping individuals. Large guilds could take minutes per reminder, holding the tick mutex.

**Fix implemented:** Daily reminders use a **role mention** (`<@&roleId>`) — one channel POST, no member fetch.

### RC-2: Gateway member cache never populated

The gateway listened for member chunks but:

- Never sent opcode 8 (`REQUEST_GUILD_MEMBERS`) on `GUILD_CREATE`.
- Listened for wrong event name `GUILD_MEMBERS` instead of `GUILD_MEMBERS_CHUNK` (Discord v10).

**Fix implemented:** Request chunks on `GUILD_CREATE`, rate-limited queue, correct `GUILD_MEMBERS_CHUNK` handler, ready logging.

### RC-3: `tick skipped` breaks automatic reminders

When `tickInFlight` is set, the entire minute is abandoned — no guild processing. Reminders use `matchesSchedule` (exact minute). If that minute is skipped, **no retry until the next day** (`lastReminderDate` unchanged).

Sustained skip storms (Jun 17 03:01–05:50) **directly caused missed reminders**. A single skip at deploy is usually harmless unless it coincides with the reminder minute.

**Fix implemented:**

- Fast reminders (mutex rarely held long).
- `matchesScheduleWithGrace` — 1 minute after scheduled time still fires if not yet sent.
- Per-guild / whole-tick timeouts, mutex force-release (prior work).
- Removed duplicate startup tick; added `tick started` / `tick finished in Xms` logs.

### RC-4: Deferred commands without follow-up timeout

`/standup start` deferred correctly but `runDailyReminder` could hang indefinitely.

**Fix implemented:** 90s `withTimeout` on all deferred follow-ups; step logging.
